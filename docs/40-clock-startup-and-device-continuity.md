The fast cancellation trace exposes a startup reset loop: video already has two valid sender reports while audio still has only one. Each unavailable audio clock used to invalidate the independently valid video anchor. The reset serial reaches 63 before any media commits. Before the first media commit, unavailable audio now rejects all incoming and queued PCM while preserving a fresh valid video anchor. It cannot grant permission, establish audio ordering or refresh video lifetime. After media has committed, lost clock evidence still invalidates playback. Stale or invalid video retains its existing reset behavior.

The coordinated adapter also waits for valid queued PCM before preparing or starting the output device. Its worker waits for ingress/presentation notifications in this startup state rather than polling the device every two milliseconds. Once media is running, the existing endpoint wake/poll behavior remains. Deterministic controls reproduce both startup failures before the change, then require no output preparation or sample commits without trained audio, exact fresh PCM on valid startup, and retained clock-loss fencing after playback begins.

Consecutive WASAPI writes address consecutive device frames. The endpoint now preserves the end of the last successfully committed packet when a new valid device observation moves backward by at most 5 ms. The corrected deadline must still be in the existing 0–30 ms lead domain, and the observation itself must be valid and not already due. This bounds the difference from the current raw observation rather than accumulating an unlimited correction. It adds no PCM queue.
